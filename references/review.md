# 校正の確認

原文と資料を保存し、校正稿を別名で作る。`check.py run` は校正稿のlint、全文差分、意味が変わった可能性のある箇所をJSONへ保存する。

## 読み比べる内容

主体と対象を確認し、数値を同じ条件で読めるかを見る。報告元と日時、肯否、推量の強さも確認する。依頼・予定・実績はそれぞれの働きを保つ。

「申込書の重複を把握していない」を「重複はない」にすると、把握状況から存在の否定へ主張が変わる。「来月追加する予定」を「追加した」にすると予定が実績になる。こうした変化は原文と資料の該当文へ戻って判断する。

重複する条件をまとめた場合は、その条件が残る文を確認する。主張をつなぐ理由や用語の説明も通して読む。

## 機械が示す差

数値・識別子・URL・コードの追加と削除を表示する。追加値が資料中にもある場合は、その一致も記録する。確かさや検証状態を表す語が変わった文には、原文と校正稿の候補を添える。

対応する文は文字列の近さから探す。文の分割や移動は全文差分で確認する。意味の確認には変更箇所全体を読む。候補は読み直す場所を示す。

## 出典への書き換え

筆者の未実施を添えた断りはS08の書き換え対象となる。仕様や一般的な動作は内容から述べ、参照を添える。個別の観測結果や紹介する手順には報告元を示す。差分の `attribution_reframe` では移動先の出典表示と条件を確認する。

`source_wording_change` は説明用の出典名を省いた候補を示す。資料がその説明を支え、参照と適用条件が保たれているか読む。測定値・見解・特定の時点の報告は、発信元が分かる形を保つ。詳しくは [情報の種類と出典](attribution.md) を参照する。

筆者自身の追試と引用結果を比較するなど、利用者が検証方法の明示を求めた場合はその依頼文を `--author-method-request request.md` で指定できる。記録には依頼文のパスとハッシュを保存する。通常の調査記事は出典への書き換えで仕上げる。

## 否定の結びを比較する

`comparison.style_change` に原文と校正稿の否定終止、定型的な否定の結び、筆者の断りを記録する。新しく加わった結びは `negative_closure_change` として原文と比べる。必要な検証状態や禁止は保ち、重複した解釈の指示を整理する。

## 実行例

```bash
python scripts/check.py run --source original.md --final final.md --material facts.md --record review.json
python scripts/check.py verify --final final.md --record review.json
```

`--material` は複数指定できる。`run --json` は保存した記録を標準出力にも返す。

記録には原文・校正稿・資料・履歴・検査ツールのSHA-256が入る。`run` はS08を含む検査記録を保存する。S08が解消すれば終了コード0、書き換えが必要なら1を返す。`verify` はファイルの一致と現在のS08を再確認する。変更や未処理のS08は1、読取り・引数のエラーは2。意味の確認は本文を読む工程で行う。

Git作業の記録を日付で選ぶ方法は[補助モード](../docs/progress.md)を参照する。差分にはファイル全体が入り、過去の記録への変更も確認できる。

## 生成検証

比較に使うモデルと推論設定を決め、入力とスキルの版を記録する。各条件は別の会話で実行し、共通資料から始める。利用者による指定はその検証の条件として扱う。手順は[開発ガイド](../docs/development.md)を参照する。
