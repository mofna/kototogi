# kototogi（こととぎ）

書き手の語り口と意味を保ちながら、日本語の文章を読みやすく整えるAIエージェント向けスキルです。技術記事や設計メモ、調査報告からチャットの返答まで使えます。

回りくどい前置きや繰り返す説明を整理し、段落の順序と文を見直します。語尾や口語は原稿を基準にします。

## 校正例：CSV取込みの改善を伝える

架空の取込ツールを題材にした作例です。原稿の背景・実装・検証結果を残して推敲しています。測定値や予定は[例文の材料](references/examples.md)に示した設定です。

### 校正前

> 30万件のCSVを読み込ませたら、取込中のメモリー使用量が気になった。小さいファイルなら平気だったので、つい後回しにしていたんだよね。実装を見たところ、`csv.DictReader`の結果を全部リストにしてからDBへ渡していた。ここで重要なのは、単なる読込み処理の置き換えではなく、メモリーに保持する件数を見直すことだ。
>
> そこで、読みながら、1,000件ずつDBへ書き込んで確定し、端数も最後に書き込む形へ変えた。これが地味に効いた。同じ30万件を同じ検証環境で4回ずつ取り込み、各回の最大メモリー使用量の中央値は512 MiBから96 MiBへ減った。この数値はこの環境での測定結果であり、すべての環境の結果ではない。
>
> 必須項目が空だったときはレコード番号を出して停止する。確定済みの分はDBに残り、処理中の分は書き込まない。検証では4,312件目のエラーで停止し、先頭の4,000件が残った。次はこの番号を手掛かりに、再開位置を指定するオプションを追加する予定だ。これは実装済みという意味ではない。

### 校正後

> 30万件のCSVを読み込ませたら、取込中のメモリー使用量が気になった。小さいファイルなら平気だったので、つい後回しにしていたんだよね。
>
> `csv.DictReader`の結果を全部リストにするのをやめ、読みながら1,000件ずつDBへ書き込んで確定する形に変えた。端数も最後に書き込む。同じ30万件を同じ検証環境で4回ずつ取り込むと、各回の最大メモリー使用量の中央値は512 MiBから96 MiBへ減った。
>
> 必須項目が空ならレコード番号を出して停止する。確定済みの分はDBに残り、処理中の分は書き込まない。検証では4,312件目のエラーで停止し、先頭の4,000件が残った。次はこの番号を手掛かりに、再開位置を指定するオプションを追加する予定だ。

最初の段落に困ったこと、次に変更と測定結果を置きました。環境と実装予定を言い直す結びを省き、失敗時の処理は残しています。「つい後回しにしていたんだよね」という書き手の調子もそのままです。

[検索APIの例](references/examples.md)では設計理由とSQLのつながりを、[分割アップロードの例](references/attribution.md)では仕様・手順・測定結果の出典の示し方を扱っています。

## 使い方

AIエージェントに`SKILL.md`を読ませ、原稿と必要な資料を渡してください。ファイルを編集する場合は保存先も指定します。

```text
kototogiを使ってdesign.mdを推敲してください。
語り口と内容を保ち、重複や回りくどさを整理してください。
修正版はdesign.revised.mdへ保存してください。
```

短い文章は依頼文に直接貼れます。レビューだけなら「該当箇所と理由を示してください」と指定してください。新しく書く場合はメモや資料を渡します。

## 点検すること

構成を見直してから語句や読点を整え、原文と資料を読み比べます。同梱ツールは再読する箇所と全文差分を示す役割です。AIエージェントが文脈を読み、数値や条件と主張の確かさを確認します。

検出された語も文脈に合えば残します。文体の集計値は傾向を読む参考にし、編集は説明の明確さを基準にします。

## 導入

`kototogi`フォルダーを、利用するAIエージェントのスキル配置先へ置いてください。直接読み込ませる場合は`SKILL.md`の場所を指定します。

診断ツールにはPython 3.10以降を使います。追加パッケージは不要です。[利用手順](docs/usage.md)にコマンドの説明、[開発ガイド](docs/development.md)にテストと配布の手順があります。
