# 開発ガイド

診断ツールは再読候補を示し、AIエージェントが文脈から編集する。規則の変更は検出例と維持する例の両方で確認する。

## 実装と例文

標準ライブラリと同梱処理を優先する。Markdownの解析は文章の点検に必要な構文を扱い、語句は`references/features.json`から読む。既存処理を共用し、呼出し元のない処理を削る。

公開例は技術分野から選び、背景や理由を追える長さにする。話題ごとに校正前と校正後を続けて置き、変えた理由を短く添える。条件や数値は該当する文に含める。作成方法や実行条件は生成検証の記録で管理する。

テストは異なる動作を確かめる最小の組にする。同じ準備や呼出しはまとめ、文書の言い回しは通読で判断する。

## 動作と文書を確かめる

```bash
python -B -m unittest discover -s tests -v
python -B scripts/lint.py SKILL.md --self-check
python -B scripts/lint.py README.md --self-check
```

`--self-check`は規則文書の用語説明を扱う。記事やチャットの本文には通常モードを使い、候補を確認した後に全文の流れを読む。

依存関係の試験はimportを調べ、追加パッケージと外部コマンドを使えない条件でCLIを実行する。

## 生成文で比較する

比較条件にはモデルと推論設定、入力とスキルの版を記録する。利用者の指定があればそれを採用し、各条件は独立した会話で同じ材料から始める。

採用する出力の選び方を先に決め、コードや数値と主張の確かさを原稿と比較する。診断件数と文章の読みやすさを両方確かめる。

公開前の確認とZIP作成は[配布ガイド](release.md)を参照する。
