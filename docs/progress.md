# Git作業の進捗記録を点検する

AIエージェントがリポジトリの変更や検証結果を日付ごとに報告する場面で使う補助機能です。対象日の原稿と過去の記録を渡すと、共通説明の繰り返しを点検できます。

`--kind progress-log`でこのモードを選びます。文章の読み直しには、渡されたGit履歴やレビュー記録を材料として使います。ツールはMarkdownの解析を担当し、リポジトリへの操作は呼出し元で管理します。

## 日付と履歴を選ぶ

`progress.md`に`## 2025-04-09`のような日付見出しがある場合の例です。

```bash
python -B scripts/lint.py progress.md --kind progress-log --entry-date 2025-04-09
```

他の日付は共通説明の比較に使います。別ファイルの履歴は次のように渡せます。

```bash
python -B scripts/lint.py today.md --kind progress-log --history history.md
```

校正前後を比べるときは`check.py run`にも同じ引数を付けます。検査対象日はlintの範囲を選び、全文差分には過去の記録への変更も表示されます。

## 当日の報告を整える

作業内容と確認した結果を中心に記します。共通の集計方法は参照できる場所へまとめ、過去の日付は当時の状態を保ちます。コミット数やPR数を示す場合は集計対象を添えてください。

以下は架空の検索インデックス作成CLIの報告例です。集計方法は共通の説明へ記載済みで、当日はGit履歴とCI記録を材料にしています。

### 校正前

````markdown
検索インデックス作成CLIに`--exclude`を追加する変更と既存のエラー表示の修正をまとめたPRを1件統合した。これはPRの統合件数であり、独立した機能数とは分けて考える。`--exclude '*.tmp'`で一時ファイルを対象から外せる。拡張子の大文字小文字を区別する仕様はそのままだ。

CIではUTF-8の文書を使った12ケースが成功した。ただし、これはUTF-8入力での結果であり、全形式への対応を確認した結果ではない。Shift_JIS入力で文字化けするケースは修正中で、次はその読込み処理を直す。日次集計のための追加テストは行っていない。
````

### 校正後

````markdown
検索インデックス作成CLIに`--exclude`を追加する変更と既存のエラー表示の修正をまとめたPRを1件統合した。`--exclude '*.tmp'`で一時ファイルを対象から外せる。拡張子の大文字小文字を区別する仕様はそのままだ。

CIではUTF-8の文書を使った12ケースが成功した。Shift_JIS入力で文字化けするケースは修正中で、次はその読込み処理を直す。
````

PRの件数と修正内容を示し、CIの結果から次の作業へつなげました。UTF-8の成功とShift_JISの問題は、それぞれの入力条件と一緒に残しています。共通の集計方法は参照できる形にし、過去の日付の記録は当時の状態を保ちます。
